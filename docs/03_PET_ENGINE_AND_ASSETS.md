# 03. 펫 엔진과 그래픽 에셋

## 1. 구현 목표

같은 이동 엔진에서 고양이와 강아지 정의를 사용한다. 캐릭터 이미지가 바뀌어도 이동과 저장 코드를 다시 작성하지 않는다. 다만 여러 종류를 위한 추상 클래스와 플러그인 시스템을 먼저 만들지는 않는다.

산책 범위는 현재 보이는 웹페이지의 가로와 세로 전체다. 페이지 요소를 분석해 발판을 찾거나 물리 엔진을 적용하지 않는다. 핵심은 위치 계산, 행동 전환, 렌더링, 생명주기를 작게 분리하는 것이다.

## 2. 세 계층

| 계층 | 책임 | 금지 |
| --- | --- | --- |
| Core | 좌표, 상태 전이, 경계 계산, 시간과 난수 입력 처리 | DOM, React, Chrome API 호출 |
| Runtime | rAF, 행동 타이머, Pointer Events, 화면 크기와 표시 조건 연결 | 저장된 전체 상태를 프레임별 변경 |
| Renderer | 위치 transform, 방향, 이미지 프레임, UI 반응 | 독자적인 영속 데이터 쓰기 |

코어에는 clock과 RNG를 주입할 수 있어야 한다. 테스트에서는 고정 seed 또는 가짜 RNG를 사용한다. 테스트에서 Math.random 결과에 의존해 우연히 통과하는 구조를 피한다.

React는 host 안의 캐릭터 컨테이너와 메뉴를 마운트하고, 행동의 큰 변화만 반영한다. 연속 좌표는 ref로 보관해 DOM의 transform을 갱신한다. 같은 transform을 React style과 엔진이 서로 덮어쓰지 않도록 소유권을 정한다.

## 3. 좌표와 이동

좌표는 뷰포트 왼쪽 위를 원점으로 하고 CSS px 단위를 쓴다. 펫의 레이아웃 박스 왼쪽 위를 x/y로 정의한다. 페이지의 스크롤 위치는 더하지 않는다.

산책 경로의 기본 여백은 16px이다. 일반 크기의 화면에서 산책 범위는 다음과 같다.

```text
minX = 16
minY = 16
maxX = viewportWidth - petWidth - 16
maxY = viewportHeight - petHeight - 16
```

화면이 매우 작아 위 여백까지 유지할 수 없으면 여백을 줄이고 표시 크기를 임시 축소해 뷰포트 안에 들어가게 한다. 이 임시 보정은 저장된 크기 설정을 바꾸지 않는다. 창 크기, 확대/축소, 크기 설정 변경 시 범위를 다시 계산하고 좌표를 보정한다. 드래그, 고정 위치 및 그 자리에서 재개한 산책에는 산책 여백을 적용하지 않는다. 펫이 화면 안에 온전히 들어가도록 x는 0~(뷰포트 너비 − 펫 너비), y는 0~(뷰포트 높이 − 펫 높이) 사이에서만 보정한다.

각 탭은 같은 펫 ID에서 길이와 각도가 다른 구간들을 만든다. 실제로 걸은 거리만큼 두 축으로 이동하고 경계에 닿은 축만 반사한다. 같은 시각에는 같은 상대 위치와 행동을 표시하며, 입체 모형은 현재 창에서의 이동 방향을 향한다. 쉬는 시간은 이동 거리에 더하지 않는다. rAF는 보이는 화면을 그리는 데만 쓴다. [S10]

고정 위치는 뷰포트에서 펫 크기를 뺀 가용 공간의 x/y 비율로 표현한다. 가로 중앙, 맨 위에 놓으면 크기가 다른 창에서도 가로 중앙, 맨 위에 보인다.

## 4. 행동 상태 머신

행동과 실행 중지 사유를 분리한다. `SLEEP`은 캐릭터 연출이고, `document.hidden`은 계산을 멈추는 생명주기 조건이다.

| 상태 | 동작 | 기본 지속 시간 | 다음 상태 |
| --- | --- | --- | --- |
| IDLE | 제자리 대기 | 2~5초 | WALK, SIT, SLEEP |
| WALK | 화면 안에서 여러 각도로 이동 | 3~8초 | IDLE |
| SIT | 앉기 | 4~9초 | IDLE |
| SLEEP | 잠자기 연출 | 20~40초 | IDLE, 사용자 반응 |
| PETTED | 쓰다듬기 반응 | 약 0.8초 | IDLE 또는 열린 메뉴 대기 |
| DRAG | 잡은 곳을 중심으로 흔들리며 발이나 날개를 움직임 | 포인터를 놓을 때까지 | 끌었다면 놓은 좌표에 고정 |

걷기와 휴식 순서는 같은 펫과 기준 시각으로 재현할 수 있다.

사용자 드래그가 자동 행동보다 우선한다. 클릭하면 자는 펫도 반응할 수 있다. 메뉴와 키보드 포커스는 해당 페이지의 조작 대상을 제자리에 유지한다. 고정 여부는 클릭 반응과 독립적이다. 메뉴를 닫아도 고정 위치는 유지하며, ‘산책 다시 시작’을 선택해야 고정을 풀고 그 위치에서 대각선 산책을 시작한다. 기본 여백은 기본 산책에만 적용하며, 화면 끝에서 재개해도 시작점을 안으로 옮기지 않는다.

실행 중지 사유는 집합으로 관리한다. 예를 들어 메뉴를 닫아도 문서가 여전히 숨겨져 있으면 재개하면 안 된다.

```text
렌더러 없음: 전체 disabled 또는 일반 창이 아님
임시 숨김(렌더러 해제): 창 포커스 없음, 비활성 탭, 탭 숨김
자동 이동 중지: 드래그로 위치 고정, 펫 키보드 포커스, 메뉴 열림, reduce motion
실행 중단: context invalidated 또는 document teardown
```

reduce motion은 무조건 렌더러 제거가 아니라 정적 표시다. 전체 표시를 끄면 새 문서와 bfcache 복원에도 같은 설정이 적용된다.

## 5. 프레임과 타이머 운영

산책의 위치 갱신 루프는 WALK일 때만 돌린다. 고정 상태에서는 위치 루프와 다음 행동 타이머를 중지한다. IDLE/SIT/SLEEP은 하나의 다음 행동 타이머와 필요한 CSS 스프라이트로 표현한다. DRAG의 위치는 포인터 이벤트로만 바뀐다. 자세는 잡고 있는 동안 16장 루프를 사용하며, 커서가 멈춰도 발은 움직인다. 기울기와 자세는 탭에서만 그리며 추가 rAF나 영속 저장을 만들지 않는다. 동작 줄이기에서는 한 자세만 표시한다.

모든 실행 상태를 통틀어 위치 갱신 루프는 인스턴스당 최대 하나다. 렌더링과 행동마다 별도 rAF를 동시에 여러 개 돌리지 않는다. DOM 크기는 resize나 설정 변경 때 읽고 프레임마다 `getBoundingClientRect()`를 호출하지 않는다.

창이 표시 조건을 잃거나 문서가 숨겨지면 렌더러를 제거해 rAF와 행동 타이머를 취소하고 CSS 애니메이션도 종료한다. 숨겨진 동안에는 표시 조건과 설정 변경만 구독한다. 복귀하면 현재 시각의 공유 위치와 행동을 표시한다. 이미 고정한 펫은 복귀 후에도 고정한 위치에 머문다. 장시간의 숨김을 빠르게 재생해 따라잡지 않는다. Page Visibility API를 사용하되 모든 창이 가려지는 OS 상황까지 완벽하게 판별한다고 약속하지 않는다. [S11]

## 6. 렌더링과 스타일 분리

WXT `createShadowRootUi`와 `cssInjectionMode: 'ui'`를 기본으로 사용한다. 상위 사이트에 CSS reset이나 Tailwind preflight를 흘리지 않는다. [S1]

UI 레이어는 fixed 배치, 화면 크기에 맞는 영역, pointer-events none을 사용한다. 펫과 메뉴에만 pointer-events auto를 준다. 펫 위치용 외부 wrapper와 방향 반전용 내부 wrapper를 분리한다.

```text
shadow host
  └─ overlay root: 고정 레이어, pointer-events none
       ├─ pet position wrapper: translate3d(x, y, 0)
       │    └─ facing wrapper: scaleX(1 또는 -1)
       │         └─ sprite 또는 placeholder: pointer-events auto
       └─ menu: pointer-events auto
```

이동과 방향을 같은 style.transform에 각각 대입하면 한쪽이 사라질 수 있으므로 분리한다. 메뉴는 반전 wrapper 밖에 둬 글자가 거꾸로 되지 않게 한다.

Shadow DOM 안에서도 font, color, line-height 등 상속 속성을 명시한다. 크기 토큰은 px 또는 내부 em을 사용한다. rem은 사이트 루트 글자 크기의 영향을 받을 수 있어 오버레이의 고정 치수에 의존하지 않는다. React portal을 사용하는 UI를 추가하면 반드시 같은 Shadow Root 안에 목적지를 지정한다.

큰 z-index가 top layer의 dialog나 모든 사이트의 레이어보다 위를 보장하지는 않는다. 페이지 모달을 뚫고 올라가려 하지 않는다. 상위 document의 transform 등으로 위치가 비정상인 특수 사이트는 안전하게 숨기거나 알려진 제한으로 기록한다.

## 7. 클릭과 드래그

Pointer Events를 사용한다. 주 포인터의 왼쪽 버튼만 드래그를 시작하고 해당 pointerId를 추적한다. 펫에서 `setPointerCapture`를 설정해 이동 중 마우스가 펫 밖으로 나가도 이벤트를 받는다.

포인터 시작 좌표에서 6 CSS px 미만 움직인 채 놓으면 클릭으로 판단한다. 임계값 이상이면 DRAG로 전환하고 클릭 효과와 메뉴 열기를 억제한다. 포인터의 펫 내부 잡은 위치를 기억해 드래그 시작 때 그림이 갑자기 점프하지 않게 한다. 움직이지 않아도 180ms 이상 누르고 있으면 들어 올린 자세를 보여 주되 드래그로 판정하지는 않는다.

native 이미지 드래그, 펫 내부 텍스트 선택은 막는다. 하지만 문서 전체에 `preventDefault`를 걸거나 페이지의 텍스트 선택을 끄지는 않는다. 메뉴 외부 클릭으로 메뉴를 닫더라도 원래 페이지의 링크 클릭을 취소하지 않는다.

드래그 중 미리보기는 저장하지 않으며 포커스된 일반 창에서만 그린다. 놓으면 capture를 해제하고 마지막 위치 비율을 프로필에 고정한다. 취소하면 마지막 공유 상태로 돌아간다. 새로고침과 전체 표시 변경으로는 고정이 풀리지 않는다.

`pointercancel`, `lostpointercapture`, 창 포커스 상실, 페이지 숨김, 렌더러 제거에서도 드래그가 고착되지 않도록 정리한다. 실제 capture가 없어진 상태에서 release를 호출하는 예외를 처리한다. 펫 이외 영역의 포인터 이동을 계속 추적하지 않는다.

### 돌봄 동작

펫을 클릭해 메뉴를 여는 하트 반응과 보상을 주는 명시적 쓰다듬기를 구분한다. 쓰다듬기 보상을 다시 받을 수 없는 동안에도 반응은 보여 줄 수 있다. 먹이를 줘도 고정 위치나 산책 경로는 바뀌지 않는다. 돌봄 수치는 산책 프레임 및 타이머와 분리한다. 펫은 배가 고파도 사라지거나 병들지 않는다.

## 8. 에셋 없는 시작

현재 최종 고양이/강아지 이미지 파일은 제공되지 않았다. 존재하지 않는 PNG 경로를 만들어 놓고 완료라고 보고하지 않는다.

P1에서는 순수 CSS 도형으로 만든 **임시 고양이 렌더러**를 작성한다. 제자리 반응과 방향 전환만으로도 위치 엔진을 검증할 수 있다. 운영체제마다 달라지는 이모지를 최종 그래픽으로 간주하지 않는다. 임시 그래픽이라는 사실은 개발 기록과 미리보기에 표시한다.

P2에서는 placeholder를 사용해 동작을 검증하면서 스프라이트 계약과 렌더러를 준비한다. 실제 에셋이 없으면 테스트용 색상 셀 fixture 등으로 프레임 계산만 확인하고, 최종 스프라이트 적용은 미완료로 기록한다. 최종 그래픽이 승인되지 않았더라도 기술 시제품은 진행할 수 있지만 P6 외부 출시 게이트는 통과하지 못한다.

P7-B의 강아지는 이 프로젝트에서 직접 도형으로 그린 로컬 렌더러다. `features/pet/definitions/species.ts`가 두 종류의 ID, 표시 이름과 대체 동작을 관리한다. 현재 두 캐릭터 모두 스프라이트 없이 동작한다. 새 모습을 선택해도 산책이나 고정 좌표를 다시 계산하는 새 펫을 만들지 않는다.

## 9. 스프라이트 계약

첫 캐릭터의 권장 원본 셀은 32x32px, 기본 표시 크기는 64px다. 셀 크기는 캐릭터 정의에서 바꿀 수 있지만 한 clip 안의 모든 셀은 같아야 한다. 기본 바라보는 방향은 오른쪽으로 통일한다.

| 항목 | 조건 |
| --- | --- |
| 포맷 | 투명 PNG, 로컬 번들 |
| 셀 | 같은 폭/높이, 프레임 간 간격과 바깥 여백 없음 |
| 방향 | 기본 오른쪽, 왼쪽은 좌우 반전 |
| 기준점 | 발의 기준선과 위치가 프레임 사이에 흔들리지 않음 |
| 배경 | 알파 투명, 체크무늬가 이미지에 그려져 있지 않음 |
| 크기 | 현재 셀 크기의 정수 배율 표시 우선 |
| 렌더링 | image-rendering: pixelated |
| 필수 모션 | IDLE, WALK |
| 권장 모션 | SIT, SLEEP, PETTED |
| 대체 모션 | 드래그 및 고정 중에는 IDLE 또는 전용 정적 프레임 |

권장 프레임 수는 idle 2~4, walk 4~8, sleep 2~4다. 이는 외부 파일에 반드시 존재하는 프레임 수가 아니라 에셋 제작/선정 기준이다. 실제 파일을 검사해 메타데이터를 작성한다.

```ts
type AnimationName = 'idle' | 'walk' | 'sit' | 'sleep' | 'petted';

interface SpriteClip {
  path: string;                 // 실제 존재하는 확장 내부 리소스 경로
  frameWidth: number;
  frameHeight: number;
  columns: number;
  frameCount: number;
  framesPerSecond: number;
  loop: boolean;
}

interface PetDefinition {
  id: string;
  displayName: string;
  defaultFacing: 'right';
  renderer: 'placeholder' | 'sprite';
  clips: Partial<Record<AnimationName, SpriteClip>>;
  fallbackAnimation: 'idle';
}
```

이 계약을 구현할 때 renderer가 sprite이면 idle과 walk를 필수로 검증한다. placeholder이면 clips가 없어도 된다. 추가 모션이 없으면 idle로 대체한다. 없는 clip을 계속 재생하려다 화면에서 사라지게 하지 않는다.

clip의 frame i에 대해 다음 좌표를 계산한다.

```text
column = i % columns
row = floor(i / columns)
backgroundX = -(column * frameWidth * scale)
backgroundY = -(row * frameHeight * scale)
```

단일 행 이미지는 CSS steps 애니메이션을 사용할 수 있다. 여러 행 또는 불규칙 재생은 하나의 관리된 프레임 스케줄러로 처리한다. 마지막 프레임 뒤 빈 영역을 보여 주는 off-by-one 오류를 테스트한다. JS 프레임 방식을 쓰더라도 상태와 좌표의 React 재렌더는 매 프레임 수행하지 않는다.

MVP의 크기 32/64/96은 32px 셀 기준 1/2/3배다. 원본 셀을 변경했다면 프레임 절단, 표시 크기, 히트 박스, 메뉴 위치를 함께 검증한다.

## 10. 에셋 승인 기록

무료, 유료, AI 생성 여부와 무관하게 출처와 사용 조건을 확인한다. 경쟁 서비스의 캐릭터, 공식 게임 캐릭터, 검색 결과의 이미지를 임의로 가져오지 않는다. 유료 에셋의 원본 재배포 제한과 공개 Git 저장소에 넣을 수 있는지 여부는 별도로 확인한다.

실제 선택 후 아래 표를 업데이트한다. 현재 승인된 외부 에셋은 없다.

| 캐릭터/파일 | 출처/제작자 | 라이선스 또는 계약 | 확장 번들 배포 | 원본 저장소 공개 | 수정/출처 표기 | 상태 |
| --- | --- | --- | --- | --- | --- | --- |
| 살구 줄무늬 고양이 (Cat.tsx) | 이 프로젝트에서 Codex로 작성한 SVG 경로와 CSS 포즈 | 외부 에셋 사용 없음 | 로컬 개발 번들 | 별도 결정 | 프로젝트 안에서 수정 | 디자인 후보, 출시 승인 전 |
| 접힌 귀 비스킷 강아지 (Dog.tsx) | 이 프로젝트에서 Codex로 작성한 SVG 경로와 CSS 포즈 | 외부 에셋 사용 없음 | 로컬 개발 번들 | 별도 결정 | 프로젝트 안에서 수정 | 디자인 후보, 출시 승인 전 |

두 동물의 귀, 무늬, 얼굴, 몸, 꼬리와 잠든 모습은 외부 캐릭터 그림이나 템플릿의 벡터를 가져오지 않고 코드로 그렸다. 눈과 스카프의 공통 요소는 같은 디렉터리의 `Ink.tsx`에 있다. 제작 경위 기록과 최종 디자인 승인은 별개다.

임시 렌더러를 정식 디자인으로 발전시키는 경우에도 사용자의 디자인 승인과 실제 제작 경위를 기록한다. 자동 생성했다고 해서 독점 권리나 무조건적인 상업 사용 가능성을 보장하지 않는다.

## 11. 핵심 엔진 테스트

렌더링 빈도와 문서를 연 시각이 다른 탭이 같은 시각에 같은 상대 위치와 행동을 표시하는지 확인한다. 경계 좌표, 작은 뷰포트, 좌우 반전, 드래그 오프셋, 숨김 후 긴 dt, 고정 후 창 크기 변경, 중복 start/stop을 테스트한다.

행동 전이는 불가능한 상태로 이동하지 않아야 한다. 메뉴나 키보드 포커스가 이동을 멈추고, 다른 중지 사유가 남아 있으면 재개하지 않아야 한다. 성능 목표와 실제 사이트 체크리스트는 테스트 문서를 따른다.

공식 출처 ID는 `05_TESTING_AND_RELEASE.md`에 정의되어 있다.

### 동물 10종의 원화

고양이와 강아지 기존 원화에 토끼, 햄스터, 여우, 수달, 레서판다, 고슴도치, 펭귄, 오리를 더했다. 신규 원화는 프로젝트 안의 `features/pet/rendering/Friend.tsx`에서 직접 그린 SVG로, 외부 에셋을 다운로드하거나 구매하지 않았다. 같은 렌더러를 웹페이지, 팝업 초상, 크기 견본, 포즈 수첩, 옷장에서 사용한다. 공개용 최종 원화 승인은 별도다.

### 옷장 원화

평상복인 데님 멜빵바지와 크리스마스의 산타 코트, 솔잎 요정복, 순록 조끼는 `features/pet/rendering/Clothes.tsx`에서 직접 그린 SVG다. 몸통 안에 옷을, 머리 안에 모자나 머리띠를 놓아 기존 포즈와 함께 움직인다. 종별로 머리 위치와 크기가 다르고, 별도 낮잠 원화가 있는 고양이와 강아지는 웅크린 몸에 맞는 착장을 사용한다. 외부 에셋은 사용하지 않았다.
