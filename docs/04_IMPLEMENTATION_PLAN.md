# 04. 단계별 구현 계획

## 1. 진행 원칙

한 요청에서 한 단계만 구현한다. 이번 패키지의 기본 시작점은 P0이며, P7은 사용자가 별도로 선택하기 전에는 시작하지 않는다. 앞 단계에서 필요한 최소 구조는 먼저 만들되 후속 기능까지 숨겨서 구현하지 않는다.

진행 상태는 `TODO`, `IN_PROGRESS`, `VERIFY_PENDING`, `BLOCKED`, `DONE`을 쓴다. 구현 완료와 실제 검증 완료를 구별한다. 수동 검증이 남아 있으면 VERIFY_PENDING이다. 기능상 선행 검증이 실패한 상태에서 다음 단계로 넘어가지 않는다.

외부 사이트나 실제 Chrome 검증을 에이전트가 수행할 수 없다면 재현 절차를 작성하고 사용자 결과를 기다리는 상태로 기록한다. 시행하지 않은 테스트를 통과 처리하거나 검사 자체를 지워 진행하지 않는다.

| 단계 | 목표 | 눈으로 확인할 결과 | 범위 |

## P0. 개발 환경과 실행 확인

### 선행 조건

문서 패키지와 작업 디렉터리가 준비되어 있다. 기존 코드가 있다면 먼저 조사한다. 문서만 있어도 정상이며 package.json이 없다는 사실을 오류로 취급하지 않는다.

### 수행

WXT 공식 React TypeScript 템플릿과 현재 Node 호환 조건을 확인한다. npm만 사용하고 패키지 잠금 파일을 만든다. 현재 폴더의 문서는 보존한다. 초기화가 덮어쓰기 위험을 만들면 별도 임시 폴더에서 템플릿을 생성한 뒤 필요한 파일만 병합한다.

Chrome MV3 빌드, React 팝업, Background PING/PONG, 일반 페이지의 작은 테스트 표시를 구성한다. Content Script 테스트 표시는 pointer-events none으로 만들고 사이트 레이아웃을 변경하지 않는다. P1에서 이 표시는 제거한다.

이 단계의 저장 기능은 구현하지 않는다. 나중에 필요한 storage 권한을 선언했으면 P1 사용 예정임을 기록한다. 프로덕션 권한은 다시 확인한다.

ESLint, TypeScript 검사, Vitest를 구성하고 실제 테스트 하나 이상을 실행한다. 예를 들어 메시지 envelope 검증과 PING 응답을 테스트한다. 검사가 비어 있거나 `--passWithNoTests`로 통과한 상태를 완료로 간주하지 않는다.

### 명령 계약

| 스크립트 | 역할 |
| --- | --- |
| `npm run dev` | WXT Chrome 개발 모드 |
| `npm run build` | Chrome 프로덕션 MV3 빌드 |
| `npm run zip` | WXT 배포 패키지 생성 |
| `npm run typecheck` | WXT 생성 타입 준비 후 TypeScript 검사 |
| `npm run lint` | 소스 린트, 생성 산출물 제외 |
| `npm run test:unit` | 단위/로컬 통합 테스트, watch 없이 종료 |
| `npm run check` | 타입 검사, 린트, 단위 테스트, 빌드를 순서대로 실행 |

기본 템플릿이 `compile`을 사용하면 의미를 검토해 typecheck와 연결한다. WXT `.wxt/`의 타입 준비와 tsconfig 확장은 설치 버전의 공식 방식을 따른다. Windows에서도 가능한 npm 스크립트를 사용하고 셸 전용 명령을 최소화한다.

### 완료 기준

실제 일반 페이지에서 테스트 표시가 보이고 팝업이 열린다. PING/PONG이 성공한다. typecheck, lint, test:unit, build가 성공한다. 생성된 manifest의 MV3, 팝업, worker, content script 항목을 확인한다. 수동 확인이 불가능하면 VERIFY_PENDING으로 보고한다.

### 하지 않을 것

최종 이미지 제작, 이동 엔진, 이름 저장, 육성, UI 디자인 시스템 확장.

## P1. Shadow DOM에 임시 고양이 표시

### 수행

WXT Shadow UI를 구성하고 고양이 임시 렌더러를 표시한다. 테스트 표시는 제거한다. top frame만 실행하고 문서당 한 번만 마운트한다. 페이지의 스타일과 클릭에 영향을 주지 않도록 overlay와 hit box를 분리한다.

아키텍처의 v1 루트 상태를 처음 도입한다. Background에 GET_STATE와 최소 SETTINGS_PATCH(enabled) 및 직렬 처리 경로를 만든다. 팝업의 '함께 시작하기'와 전체 표시 끄기를 연결한다. 나머지 설정은 데이터 기본값만 유지하고 아직 UI를 만들지 않는다.

읽기 구독과 렌더러를 분리해 비활성 상태에서도 다시 켜질 수 있게 한다. 저장소 쓰기를 UI에 임시로 흩어 놓고 나중에 고친다는 접근은 금지한다. 코드 크기가 작더라도 단일 writer 경계를 처음부터 유지한다.

### 완료 기준

첫 실행은 안내 화면이며 시작 버튼 후 임시 고양이가 보인다. 팝업을 닫아도 고양이는 남는다. 전체 표시를 끄고 켜면 렌더러가 제거되고 다시 나타난다. 일반 페이지의 스크롤과 고양이 밖의 클릭은 정상이다. Google, Naver, YouTube의 일반 화면에서 정적 표시를 수동 확인한다.

### 테스트

기본 상태 한 번 생성, enabled 저장/복원, onChanged 반영, host 중복 방지, UI 제거 후 다시 표시, 원래 페이지에 전역 CSS가 추가되지 않음.

## P2. 이동과 행동 엔진

### 수행

코어를 순수 함수/작은 객체로 분리하고 runtime과 renderer를 연결한다. IDLE/WALK/SIT/SLEEP을 구현한다. 공유 시간에 따른 이동, 경계 반전, resize 대응, 숨김 탭 중지와 복귀 시 현재 행동 복원을 구현한다.

임시 그래픽으로 동작을 검증한다. 스프라이트 메타데이터 타입과 검증기를 준비하되 파일 없는 경로를 만들지 않는다. 실제 에셋이 있으면 출처와 권리를 기록한 뒤 연결한다.

Playwright Chromium persistent context와 로컬 fixture를 구성하고 `npm run test:e2e`를 추가한다. 설치한 일반 Chrome에 과거의 로딩 플래그가 그대로 통한다고 가정하지 않는다. 공식 Playwright 지침을 확인한다. [S13]

### 완료 기준

사용자 조작 없이 산책과 휴식이 전환된다. 화면 밖으로 벗어나지 않는다. 30/60/120Hz 상당의 가상 dt 테스트에서 이동 속도가 프레임 수에 비례해 달라지지 않는다. 보이지 않는 문서에서는 위치 루프를 멈추고 복귀하면 현재 산책 상태를 표시한다.

### 테스트

RNG 주입 상태 전이, 시간 기반 이동, 50ms dt 상한, 경계와 작은 화면, rAF 중복 방지, visibility 전환, 동일 문서 host 한 개. E2E 환경이 실행되지 않으면 그 테스트는 통과가 아니다.

## P3. 클릭, 메뉴, 드래그

### 수행

쓰다듬기 반응(PETTED), 드래그(DRAG), 놓은 위치 고정을 구현한다. 클릭과 드래그를 임계값으로 구분하고 Pointer capture를 연결한다. 클릭은 짧은 반응과 작은 메뉴를 보여 준다. 메뉴의 쓰다듬기와 전체 표시 끄기를 연결한다.

메뉴 열림과 키보드 포커스 중에는 이동을 멈춘다. Escape, 외부 클릭, 드래그 취소, 창 포커스 상실, 문서 숨김에 안전하게 대응한다. 메뉴는 Shadow Root 내부에 렌더링한다.

현재 단계의 쓰다듬기는 시각 반응일 뿐 경험치나 행복도를 저장하지 않는다. 강제로 게임 데이터를 먼저 만들지 않는다.

### 완료 기준

드래그하면 마우스와 펫의 잡힌 지점이 유지된다. 놓으면 모든 탭에서 같은 상대 위치에 고정되고 드래그 뒤 클릭 메뉴가 잘못 열리지 않는다. 고정 중 메뉴의 ‘산책 다시 시작’을 누르면 고정한 자리에서 출발해 화면 안을 여러 방향으로 산책한다. 메뉴에서 숨기면 모든 탭에서 사라진다. 팝업에서 전체 표시를 켜면 다시 보인다. 키보드로 메뉴를 열고 닫을 수 있다. 페이지 링크, 입력, 스크롤을 막지 않는다.

### 테스트

임계값 직전/직후, capture 취소, 이동 중 창 축소, drag 중 disabled, 메뉴 외부 페이지 링크 클릭, 키보드 Enter/Space/Escape, focus 시 이동 중지, cleanup 후 리스너 해제.

## P4. 저장, 메시지, 여러 탭 일관성 완성

### 수행

PET_RENAME, 메시지와 sender 검증, 부분 변경 whitelist, requestId 중복 방지, revision 기반 읽기 갱신을 완성한다. 초기화와 오류 처리 UI를 옵션 기본 화면에 추가한다. P1의 단일 writer를 유지하며 경쟁 테스트를 강화한다.

동일 프로필의 여러 탭에서 이름, 전체 표시, 고정 위치, 산책과 휴식, 쓰다듬기 반응을 공유한다. 조작 시 기준이 되는 상태만 저장하고 프레임마다 쓰지 않는다. 서비스 워커 재시작 후 명령이 정상 처리되도록 저장 상태만으로 복원한다.

### 완료 기준

두 탭에서 서로 다른 설정을 거의 동시에 변경해도 둘 다 보존된다. 같은 필드의 마지막 승인 명령은 일관되게 반영된다. 같은 requestId 재전송은 중복 적용하지 않는다. 저장 실패 시 UI가 성공이라고 표시하지 않는다. 브라우저 재시작과 확장 새로고침 후 데이터가 유지된다.

### 테스트

아키텍처 문서의 모든 메시지 제한, 저장 경쟁, 큐 실패 복구, 저장 완료 후 응답 유실, 워커 재생성, 잘못된 스키마, 미래 스키마 보존, 손상 데이터 수동 초기화, 갱신 중 초기 읽기의 늦은 응답, 같은 ID 다른 payload 거부.

### 금지

테스트를 쉽게 만들려고 각 탭에 직접 쓰기를 허용하거나 revision만으로 트랜잭션이 생긴다고 가정하지 않는다.

## P5. 설정, 방해 방지, 생명주기와 최적화

아래는 최초 계획이다. 진행 기록 24절의 사용자 결정으로 입력, 전체화면, 사이트별 숨김은 철회했다. 해당 조건에서도 전체 표시 버튼을 따르는 것이 현재 완료 기준이다.

### 수행

옵션 화면에 크기, 속도, 동작 줄이기, 폼 포커스 숨김, 페이지 전체화면 숨김, 숨긴 hostname 목록을 완성한다. 펫 메뉴에 HOST_HIDE_CURRENT, 옵션에 HOST_UNHIDE를 연결한다.

Page Visibility, focus, Fullscreen, resize, bfcache, HMR/context invalidation과 renderer cleanup을 점검한다. 표시 조건은 하나의 컨트롤러에서 계산해 서로 다른 이벤트가 펫을 잘못 다시 켜지 않게 한다.

프로덕션 빌드로 성능 측정을 한다. hidden 상태의 rAF/행동 타이머가 0인지, idle 중 저장 쓰기가 없는지, 10개 탭에서도 보이지 않는 렌더러가 계산을 계속하지 않는지 확인한다. 여러 창이 모두 보이는 상황은 hidden 탭 테스트와 구분한다.

### 완료 기준

사용자가 방해를 받았을 때 즉시 숨기고 다시 켤 수 있다. 숨긴 hostname은 정확히 일치하는 사이트에만 적용된다. 입력값을 읽지 않고 폼 포커스만으로 숨김이 작동한다. reduced motion에서는 반복 동작을 하지 않는다. SPA, 뒤로 가기, 새로고침 반복으로 펫과 리스너가 늘어나지 않는다.

### 테스트

05 문서의 기능 시나리오 전체, 상대적으로 작은 화면/확대 화면, 드래그 중 설정 변경, 여러 중지 사유 중 한 가지만 해제, 사이트 숨김 해제 후 재표시, 잘못된 hostname 거부, 시크릿/보호 페이지의 예상 미지원.

## P6. 출시 후보 검증과 패키징

### 수행

프로덕션 빌드를 일반 Chrome에 직접 로드해 사이트 행렬과 30분 사용 검증을 수행한다. 최종 캐릭터와 확장 아이콘을 승인받고 라이선스와 필요한 attribution을 기록한다. 최종 에셋이 없으면 로컬 시제품으로 남기며 배포 준비 완료라고 표시하지 않는다.

불필요한 권한, 원격 실행 코드, 개발 URL, console 개인정보, 잘못된 이미지 URL, 중복 host를 확인한다. 업데이트 후 저장 데이터 유지도 검증한다. 안내 문구와 실제 동작을 맞추고 스토어용 설명, 개인정보 안내 초안, 스크린샷 촬영 항목을 준비한다.

`npm run zip`으로 배포 후보 ZIP을 생성하되 문서 ZIP과 혼동하지 않는다. 생성 경로와 버전, 검사 결과를 PROGRESS에 기록한다.

### 완료 기준

필수 자동 검사 통과, 실제 Chrome 검증 기록, 최종 에셋 승인, 알려진 제한 정리, 실제 동작에 맞는 권한/개인정보 안내가 모두 존재한다. 사용자의 별도 승인 없이는 계정 생성, 업로드, 공개, 스토어 제출을 하지 않는다.

스토어 심사 통과를 보장하지 않는다. 출시 준비 완료와 심사 제출, 심사 승인, 실제 공개는 서로 다른 상태로 기록한다.

## P7. 선택 확장

MVP 검증과 사용자 요청 후 P7-A 또는 P7-B 중 하나만 선택한다. '다음 단계'라는 말만으로 자동 진입하지 않는다.

### P7-A. 가벼운 육성

schemaVersion 2를 정의하고 v1의 이름과 설정을 보존하는 마이그레이션을 만든다. satiety, mood, xp, lastSettledAt, 최근 보상 시각을 도입한다. 죽음, 질병, 장기 미접속 처벌, 결제는 넣지 않는다.

시간 계산은 Background의 명령 처리에서 수행한다. 마지막 정산 시각과 현재 시각으로 감소량을 계산하고 다시 저장한다. 매초 워커 타이머를 돌리지 않는다. 탭마다 같은 감소를 독자적으로 저장하지 않는다.

초기 제안은 satiety 시간당 4 감소, mood 시간당 2 감소, 오프라인 정산 최대 8시간이며 수치는 사용자 경험 검증 후 확정한다. `effectiveNow = max(lastSettledAt, now)`를 사용해 시계가 뒤로 바뀌었을 때 음수 경과 시간을 적용하지 않는다. 정산 후 lastSettledAt을 effectiveNow로 갱신해 같은 공백 시간을 중복 계산하지 않는다.

먹이 주기와 쓰다듬기 보상은 명령별 전역 cooldown을 적용하고, 두 탭에서 같은 펫을 동시에 조작해 중복 보상하지 못하도록 단일 writer와 requestId를 재사용한다. 브라우저를 켜 놓은 시간이나 탭 수로 XP를 주지 않는다.

필수 테스트는 오프라인 상한, 시계 역행, 연속 정산, 2개 탭 정산, cooldown, 상태 범위 0~100, v1 마이그레이션이다. 구현 전에 실제 수치와 화면을 01~03 문서에 확정 반영한다.

### P7-B. 강아지 추가

라이선스가 확인된 강아지 에셋과 PetDefinition을 추가한다. speciesId 타입, registry, 선택 UI, 저장 검증과 fallback을 함께 확장한다. 기존 고양이 데이터는 유지한다. 크기와 프레임 수가 달라도 같은 엔진이 동작하는지 확인한다.

펫을 바꾸는 기능과 여러 마리를 동시에 표시하는 기능은 다르다. 동시 여러 마리는 이 단계 범위에 포함하지 않는다.

## P8. 또또와 오래 함께하고 싶은 이유 만들기

P7에서 돌봄 수치와 외형 선택을 넣었다. P8의 목표는 팝업을 열어 수치를 확인하지 않아도 웹페이지 위에서 또또의 반응을 보는 재미를 만드는 것이다. 사용자가 세 가지를 모두 선택했다. 공놀이는 성격을 표현하는 첫 장면으로 삼으며, 세 항목의 실제 검증은 보류 상태다. 출시 여부는 별도로 P6에서 판단한다.

| 항목 | 첫 버전의 범위 | 함께 써 볼 때의 판단 기준 |
| --- | --- | --- |
| P8-A 공놀이 | 일반 페이지의 펫 메뉴에서 공을 던진다. 강아지는 공을 물고 돌아오고 고양이는 앞발로 한 번 쳐서 굴린다. 보상 없이 마음대로 놀 수 있다. | 설명 없이 종별 반응을 알아볼 수 있는가? 공이 링크를 가리지 않고, 끝나면 고정 자리가 유지되는가? |
| P8-B 성격과 버릇 | 차분한 펫과 활발한 펫이 같은 신호에 다르게 반응한다. 예를 들어 놀자고 하면 먼저 고개를 기웃거리거나 바로 뛰어든다. | 이름표를 보지 않아도 두 반응의 차이를 느끼는가? 입력할 때나 전체화면일 때 먼저 방해하지 않는가? |
| P8-C 첫 액세서리 | 스카프 한 종류에 몇 가지 색을 제공한다. 미리 보고 착용하거나 벗고, 다른 탭의 같은 펫에도 적용한다. | 작은 크기에서도 색이 구분되는가? 모습 교체, 재시작 뒤에도 선택이 유지되는가? |

다음 두 후속 기능의 첫 버전을 구현했다(실제 Chrome 검증 대기).

- P9-A **놀이와 이어지는 성장:** 동물별 누적 7 XP로 태엽 쥐를 열며 XP를 차감하지 않는다. 기존 XP도 인정하고, 기본 공놀이는 첫날부터 계속 쓸 수 있다. 레벨 숫자 자체보다 새 장난감에 대한 또또의 반응을 먼저 설계한다.
- P9-B **또또의 기억:** 첫 공놀이, 태엽 쥐 놀이, 산타 코트 적용, 25분 이상 집중 완료, 하이파이브 성공을 동물별 팝업 앨범에 남긴다. 날짜, 사건, 종, 당시 이름과 차림만 기기에 보관한다. 카드 포즈는 사건과 종으로 그리며 페이지 주소나 화면은 기록하지 않는다.

- P9-C **또또의 방:** 팝업의 다락방에서 무료 방석 세 개와 벽 그림 한 장을 동물별로 고른다. 벽에는 그 동물의 실제 추억 앨범에 있는 카드 또는 기본 들꽃 그림을 건다. 실제 Chrome 검증 대기.

방문 기록이나 페이지 내용을 읽지 않고, XP 반복 획득이나 매일 출석을 요구하지 않는다. 동작 줄이기, 키보드 조작, 사이트별 숨김과 기존 위치 공유를 유지한다.
